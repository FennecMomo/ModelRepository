# 模块仓库：第一版需求与整体架构

文档日期：2026-10-22

状态：V1 需求与架构草案；已归纳讨论中的明确要求，具体技术选型为建议。

2026-10-22 使用方式修订：按用户要求，0.1.1 默认采用自用模式，打开即可管理模块，不要求初始化、登录、令牌或 CSRF。原账号与权限流程作为可选账号模式保留；取消密码最小长度、复杂度、登录限流和 localhost 初始化限制。下文角色权限描述在账号模式下适用。最新实际行为以 `stage-a-usage.md` 为准。

项目目录：`E:\etc\ModelRepository`

## 1. 产品目标

建立一个面向开发者和 Agent 的功能模块仓库，减少多个项目之间重复实现相同功能的工作。

用户上传模块代码、功能说明、API 文档和使用示例，并维护模块分类、适用环境和权限。Agent 开发前可以检索模块、判断适用性，并通过本地工具接入项目；下次开发时检查模块是否更新，将最新内容覆盖到原目录，再利用项目 Git 检查变化和处理影响。

第一版的成功标准是完成一个真实模块的“发布 → 检索 → 安装 → 发布更新 → 检查更新 → 覆盖更新 → Git 检查”流程。

## 2. 已确定的产品边界

1. 系统以模块为管理单位，模块不必分别对应 Git 仓库。
2. 使用独立后端管理模块、分类、权限和当前最新内容，GitHub 不是必要依赖。
3. 仓库只向使用者提供当前已发布内容，不承担旧版本内容备份、历史版本下载和回滚。
4. 保留当前版本标识、内容哈希和本次更新说明，用于更新检测及内容校验。
5. 模块可以由单文件或多文件组成，代码、文档、示例及必要资源属于同一次发布。
6. 模块安装、更新时写入项目指定目录；更新允许覆盖该模块受管文件中的本地修改。
7. 项目自己的 Git 负责历史记录；用户使用的 Agent 负责更新前处理工作区、更新后比较差异、分析影响和验证。
8. 不要求首次交付就有完整自动化：通过已安装的 Skill 与本地工具，先实现每次相关开发时主动检索和检查更新。
9. 第一版不依赖运行模型的服务端 AI。检索和元数据管理采用确定性的接口，语义判断主要由使用方 Agent 完成。

## 3. 角色与职责

### 3.1 使用者

| 角色 | 第一版职责与权限 |
| --- | --- |
| 管理员 | 管理账号、分类、全部模块与授权，可停用账号和模块 |
| 模块所有者 | 创建模块、维护内容、发布更新、管理该模块授权 |
| 模块维护者 | 编辑模块草稿、发布更新，不管理其他账号与模块授权 |
| 模块使用者 | 搜索、查看和下载获授权模块，接入自己的项目 |

模块所有者、维护者、使用者是模块范围的权限关系，同一账号可在不同模块中具有不同权限。

### 3.2 系统分工

| 部分 | 负责 | 不承担 |
| --- | --- | --- |
| 仓库服务端 | 模块元数据、授权、当前发布内容、搜索、下载、更新检测 | 用户项目的 Git 历史与本地代码恢复 |
| 管理界面 | 内容上传、文档填写、分类、授权、发布 | 分支管理、历史提交浏览 |
| 本地接入工具 | 下载校验、指定目录写入、受管文件清理、安装记录、结果报告 | 业务兼容性判断、自动修复调用方 |
| Skill | 指导 Agent 检索、选择、安装、更新、检查与验证 | 保证所有 Agent 平台无条件执行规则 |
| 使用方 Agent | 判断模块适用性、处理 Git 状态、分析差异、修复影响、验证 | 替仓库保存可下载的历史版本 |
| 项目 Git | 已提交代码的历史、差异与恢复依据 | 自动保存覆盖前尚未提交的内容 |

## 4. V1 功能范围

以下功能共同组成第一版完整交付范围。按实现顺序分阶段开发，但最终验收需要覆盖整个流程。

### F01. 账号、登录与工具凭据

- 管理员创建、停用账号；第一版不开放公开注册。
- 管理界面支持账号登录、退出。
- 用户可以在界面创建、撤销供本地工具使用的访问令牌。
- V1 的 Agent 令牌默认只读，能够检索、查看和下载该账号获授权模块；发布与授权操作由管理界面完成。
- 令牌与账号绑定，服务端每次请求重新检查当前账号和模块权限。
- 凭据保存在本机安全设置中，不写入项目引用清单、源码、Git、普通日志或生成的 Skill 示例。
- 单人使用时也沿用相同账号模型，避免以后重做权限体系。

### F02. 模块创建与元数据管理

每个模块具有稳定且唯一的 ID，显示名称和分类变化不改变其身份。

必填信息：

- 模块名称、功能摘要、详细说明。
- 开发语言、应用环境及明确的适用条件；无法确认的兼容范围应标记为未验证。
- 所有者、分类、标签。
- 接入方法、API 说明及最小使用示例；简单模块允许这些内容合写在一份文档中。
- 当前发布版本号和本次更新说明。

可选信息：

- 框架版本范围、操作系统和目标平台。
- 依赖项及安装要求、初始化和释放要求。
- 已知限制、验证方式与验证环境。
- 来源地址、作者及使用许可说明。

文档可以在管理界面填写，也可以随模块文件上传。服务端保存并关联到同一次发布，避免代码与说明来自不同发布。

### F03. 分类、标签与模块列表

- 管理员维护分类树；模块选择一个主分类，允许多个标签。
- 标签用于表达跨分类特征，例如 C#、Unity、Windows、Android、文件下载。
- 列表支持名称或功能关键词搜索，以及分类、标签、语言、环境筛选。
- 详情页显示功能、接口、使用示例、依赖、限制、验证说明、最新版本及更新时间。
- 搜索和列表从授权范围内筛选；未授权模块的名称、文档、数量和内容不出现在结果中。
- V1 采用字段和全文检索，不要求向量数据库、自动推荐或自然语言语义搜索。

### F04. 内容上传、草稿与发布

- 支持上传单文件、多文件或 ZIP，保留模块内相对目录。
- 支持以简单代码输入方式创建单文件模块，上传后的文件可以整体替换。
- 管理界面提供文件列表、文本预览和 Markdown 文档编辑；V1 不提供完整在线 IDE。
- 编辑形成当前草稿，使用者仍然读取当前已发布内容。
- 发布前检查必要元数据、相对路径、重复路径、包大小及文件数量等基本约束。
- 发布时生成版本标识、发布序号、文件清单和内容哈希，将内容、文档及元数据一致地切换为当前发布。
- 内容变化必须产生新的发布序号；版本号用于展示和沟通，发布序号与内容哈希用于确定是否变化。
- 不允许覆盖同一次已发布标识的内容；再次修改需要重新发布。
- 发布完成后，旧发布不再提供查询或下载；旧文件仅可因正在进行的读取、失败清理等原因短暂存在，随后清理，不形成历史备份服务。
- V1 不提供历史版本列表、历史源码、回滚和仓库内分支合并。

### F05. 模块级授权

- 模块默认仅管理员和所有者可访问。
- 所有者可以按账号授予使用或维护权限，并撤销授权。
- 授权覆盖搜索、详情、文档、清单和下载；下载地址不能绕过授权。
- 账号被停用或授权撤销后，后续访问立即按最新权限处理。
- 已下载到项目的文件无法通过撤销授权远程收回；仓库不修改用户项目现有文件。
- 第一版按账号直接授权；团队、组织、复杂继承权限和公开模块市场后续再做。

### F06. Agent 检索和内容读取

- 根据功能描述中的关键词及项目环境，返回少量候选模块摘要。
- 按模块 ID 读取完整说明、接口、示例、限制和当前发布标识。
- 获取当前发布的文件清单和内容包。
- 支持一次检查项目中多个模块的更新状态。
- 更新结果区分“已是最新”“存在更新”“不可访问或不存在”“服务不可用”等状态。
- 未授权和不存在的模块不向调用者泄露可区分的私有信息。
- 响应包含稳定 ID、发布序号、内容哈希；Agent 不依靠显示名称判断模块身份。

### F07. 指定目录安装与覆盖更新

- 本地工具接受模块 ID、项目根目录和项目内目标目录。
- 先下载并验证完整内容，再开始修改项目文件。
- 安装预检输出计划写入、覆盖、删除的路径，以及与已有文件的冲突。
- 写入范围限定为明确指定的目标目录，拒绝路径穿越、越界绝对路径，以及通过链接或重解析点逃出目录的写入。
- 模块目录之间不得重叠，防止不同模块互相覆盖。
- 对已由该模块管理的文件，按新版内容覆盖；本地修改不由本工具自动合并或备份。
- 新版移除的文件，只删除本地安装记录中属于该模块的受管文件。
- 目录内其他文件保留。首次安装或新增文件若与非受管文件重名，返回冲突，供调用方 Agent 处理后重试。
- 不执行模块携带的安装脚本；模块内容和文档作为数据读取，不作为工具级指令执行。
- 每次操作返回新增、覆盖、删除、保留、冲突和失败的结构化结果。
- 多文件写入不能假定具有完整事务性；中途失败必须报告已完成和未完成操作，留下未完成状态，不把模块记为更新成功。
- 当前发布在下载期间变化时，检测内容标识不一致并重新预检；不拼接两次发布的文件。

受管文件示例：

```text
上次安装：A.cs、B.cs
最新发布：A.cs、C.cs
目录额外存在：ProjectAdapter.cs

更新结果：覆盖 A.cs，删除 B.cs，新增 C.cs，保留 ProjectAdapter.cs
```

Unity 模块的 `.meta` 等必要资源随内容提供并保持稳定身份；V1 不自动创建预制体、修改场景绑定或执行资源迁移。

### F08. 项目安装记录与更新检测

- 在项目中保存轻量安装记录，建议路径为 `.module-repository/modules.json`。
- 记录仓库实例 ID、模块 ID、目标相对目录、已安装版本、发布序号、内容哈希、受管文件清单及必要的文件哈希。
- 不保存旧源码内容，不保存访问令牌，不保存本机专属绝对路径。
- 同一模块在同一项目中安装多个副本时，每个副本有独立安装 ID 和互不重叠的目标目录。
- 安装记录可随项目 Git 提交，使其他开发环境能够理解模块来源。
- 成功完成文件操作后才更新已安装发布记录；失败则报告未完成状态。
- 更新检查只读取安装记录和服务端元数据，本身不修改项目源码。
- 项目开发环境变化后，Agent 需重新判断适用性；服务端不把“有更新”直接等同于“兼容”。

### F09. 复用 Skill

交付一个聚焦模块复用的 Skill，以及将其接入项目开发约定的说明。

工作流：

1. 开发可复用功能前，读取项目环境和现有安装记录。
2. 查询相关模块；有候选时读取文档、依赖和限制。
3. 选用适合模块并确定目标目录；没有合适模块时说明原因并继续开发。
4. 更新前检查 Git 状态，由使用方 Agent 按用户授权处理未提交工作；仓库工具不自动提交或备份。
5. 调用本地安装或更新工具。
6. 查看 Git 差异，特别检查删除、接口变化、配置、资源引用与本地修改被覆盖的影响。
7. 修正调用方并运行与变更有关的验证，汇报结果。

第一版只在 Agent 被用户启动、且已经接入 Skill 与工具时执行流程。后台轮询、主动唤醒 Agent、跨所有平台强制触发均不在范围内。

## 5. 整体架构

```text
模块维护者
    │ 登录、编辑、上传、授权、发布
    ▼
Web 管理界面
    │
    ▼
仓库服务端 API
    ├─ 账号与模块授权
    ├─ 分类、标签与模块元数据
    ├─ 当前草稿和发布管理
    ├─ 搜索、清单和当前内容下载
    └─ 批量更新检查
    │
    ├──────── 元数据数据库
    └──────── 当前内容文件存储

用户使用的 Agent ＋ Skill
    │ 通过本地 MCP 调用
    ▼
本地接入工具
    ├─ 通过 HTTPS API 查询仓库、下载并校验
    ├─ 预检目标目录、处理受管文件
    ├─ 写入项目安装记录
    └─ 返回操作结果
    │
    ▼
用户项目目录 ＋ 项目 Git
    └─ Agent 检查差异、处理影响、运行验证
```

### 5.1 服务端边界

服务端不知道、也不直接操作用户电脑的项目目录。服务端只提供经过授权的元数据和当前内容。

数据库和内容文件共同构成服务端业务数据，应支持普通运维备份与恢复。这里的备份是当前服务数据的运维保障，与面向用户保留模块历史版本是两个范围；V1 不提供按旧模块版本恢复的产品功能。

### 5.2 本地工具边界

本地接入工具连接仓库，并在 Agent 所在环境执行目录写入。第一版提供同一核心实现的 CLI 与本地 MCP 入口，避免两套安装规则。

本地写入权限受运行环境和工具配置约束；写入目标由调用方明确给出。服务端上传的文档不能扩大本地写入范围。

### 5.3 Skill 边界

Skill 保存稳定流程和规则，不打包整套模块内容。模块最新内容通过运行时查询获取，因此模块更新不需要重新分发 Skill。

## 6. 建议数据模型

| 实体 | 关键内容 |
| --- | --- |
| User | 用户身份、管理员标记、启停状态、认证信息 |
| AccessToken | 所属用户、凭据摘要、只读范围、撤销状态 |
| Category | 分类名称、父分类、排序 |
| Module | 稳定 ID、名称、所有者、分类、标签、语言、环境、启停状态 |
| ModuleGrant | 模块、用户、使用或维护权限 |
| ModuleDraft | 当前编辑中的元数据、说明和文件引用 |
| CurrentPublication | 当前版本、发布序号、文档、依赖说明、更新时间、更新说明、内容哈希 |
| PublicationFile | 当前发布相对路径、大小、哈希、内容位置 |
| ProjectInstall（本地） | 安装 ID、仓库身份、模块 ID、目标目录、已安装发布、受管文件清单 |

不建立用于对外查询旧内容的 `ModuleVersionHistory`，也不存储旧版源码快照。V1 的依赖只记录声明和说明，不自动解析依赖图、下载依赖或修改项目包管理文件。

## 7. 建议接口

接口名称用于明确职责，开发时可以调整命名。

### 7.1 服务端 API

| 接口 | 用途 |
| --- | --- |
| 登录、退出、令牌创建与撤销 | 管理界面和工具认证 |
| 用户、分类管理 | 管理基础数据 |
| 创建、编辑、停用模块 | 管理模块身份与元数据 |
| 修改模块授权 | 按模块授予或撤销权限 |
| 上传草稿文件、编辑文档 | 准备当前待发布内容 |
| 发布模块 | 原子切换当前内容并生成发布标识 |
| 搜索模块 | 按授权、关键词和环境筛选 |
| 读取模块详情、当前清单 | 获取说明、文件清单及内容标识 |
| 下载当前内容 | 按指定当前发布标识获取一致的内容；标识已过期则返回重新检查状态 |
| 批量检查更新 | 对比项目已安装发布与当前发布 |

### 7.2 本地 MCP 工具

| 工具 | 用途 | 是否修改项目 |
| --- | --- | --- |
| `module_search` | 检索候选模块 | 否 |
| `module_get` | 读取说明与当前发布信息 | 否 |
| `module_list_installed` | 读取项目安装记录 | 否 |
| `module_check_updates` | 批量查询更新 | 否 |
| `module_plan_apply` | 校验路径，输出安装或更新计划 | 否；允许写入本地临时缓存 |
| `module_apply` | 按计划获取当前内容、校验、写入并报告 | 是 |

计划关联模块发布标识与本地文件状态；执行前重新校验。期间发生变化时返回计划过期，防止把预检之后新增的文件误当作可覆盖内容。

V1 不提供删除模块目录、恢复旧版本或自动 Git 提交工具。

## 8. 建议技术路线

以下是面向当前 Windows 开发环境的默认实施建议，不是讨论中已经确认的硬性要求：

- 服务端：ASP.NET Core，模块化单体。
- 元数据：SQLite，先覆盖单实例、个人或小团队规模。
- 内容：服务端文件目录，内容以相对路径和哈希关联；为以后接入对象存储保留接口。
- 管理界面：响应式 Web 界面，第一版与服务端一起交付，具体前端实现待开发时锁定。
- 本地工具：.NET CLI 与本地 MCP，共用下载、校验、安装和记录逻辑。
- 检索：数据库字段过滤与全文检索。
- 部署：先支持单实例部署；远程访问使用 HTTPS。开发时可以本机运行。

V1 不引入微服务、消息队列、向量数据库、GitHub 强依赖或复杂插件执行机制。跨平台客户端发布不作为首版验收项，但项目中的模块可以声明面向不同平台。

## 9. 不纳入 V1 的功能

- 模块旧版本内容备份、下载、版本回退。
- 仓库内 Git 分支、提交图、历史版本差异界面和合并管理。
- 上传模块的自动执行、远程运行与安装脚本。
- 自动修改调用方、自动判定行为兼容、自动保证升级无影响。
- 自动解析模块依赖、依赖锁定求解、批量连带升级。
- 自动扫描所有项目并提取模块、自动从新代码发布公共模块。

- GitHub、其他代码托管平台的自动同步。

- 后台推送更新、定时监控和自动唤醒 Agent。
- 卸载模块及清理其产生的业务数据。
- 跨平台客户端发行与多实例高可用部署。

## 10. 实施顺序

### 阶段 A：管理与发布

完成账号、模块、分类标签、授权、草稿上传和当前发布。管理员能够维护模块，获授权用户能够查看和下载。

### 阶段 B：本地接入

完成 CLI、下载校验、路径预检、安装记录和覆盖更新。首先用一个小型多文件模块验证新增、覆盖、删除和额外文件保留。

### 阶段 C：Agent 流程

完成本地 MCP、批量更新检查、Skill 和接入说明。使用真实项目验证 Agent 的检索、选择、安装、更新与 Git 差异检查。

三个阶段属于同一个 V1，阶段 A 完成不能称为 Agent 复用流程已交付。

## 11. V1 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 创建与查找 | 创建带源码、说明和示例的模块，可按分类、标签、语言及关键词查到 |
| A02 | 权限 | 授权账号可读和下载；未授权账号搜索、详情、清单、下载均不泄露模块；撤销后再次访问失败 |
| A03 | 发布一致性 | 代码、文档、清单来自同次发布；发布途中失败不破坏当前可用发布 |
| A04 | 初次安装 | 只写入指定目录，内容校验正确，安装记录包含来源与发布身份 |
| A05 | 更新检测 | 发布新内容后，原项目能检测到更新；检查本身不修改源码 |
| A06 | 覆盖更新 | 新文件加入、受管文件覆盖、已移除受管文件删除、目录内额外文件保留 |
| A07 | 本地定制 | 更新前 Agent 已处理 Git 状态；更新后可在项目 Git 中看到覆盖的定制及其他变化；仓库工具没有生成旧源码备份 |
| A08 | 冲突与越界 | 非受管文件重名、目标目录重叠、越界路径与链接逃逸均被识别和拒绝 |
| A09 | 失败可诊断 | 下载损坏时不开始写入；写入途中失败时明确报告部分完成，不登记成功；可在排除故障后重新计划 |
| A10 | 发布变化 | 预检后模块发布或目标文件变化，执行时检测到计划过期，重新计划后可完成 |
| A11 | Agent 接入 | 一个接入了 Skill 的实际 Agent 能完成检索、读取、安装、检查更新和更新后差异检查 |
| A12 | 运行边界 | 仓库离线时已安装项目文件仍可使用；更新检查返回不可用；系统不宣称已更新或兼容 |
| A13 | 文档与资源 | 示例中 API 与当前内容匹配；多文件和必要资源保留目录；Unity 样例保留所需 `.meta` |
| A14 | 凭据 | 项目文件、安装记录、普通日志及演示材料中不包含访问令牌 |
