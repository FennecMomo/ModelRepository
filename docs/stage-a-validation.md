# 0.1.0 阶段 A 验证记录

验证日期：2026-10-22。环境：本机 Windows、.NET SDK 10.0.401、.NET/ASP.NET Core 10.0.12、EF Core SQLite 10.0.12。

## 自动化验证

`dotnet test ModelRepository.sln -c Release --nologo`：22 项通过，0 失败、0 跳过。

覆盖的关键行为：

- 首次初始化只执行一次，写请求要求 CSRF。
- 未授权模块在列表、详情、预览、授权及下载接口不可访问。
- 使用者不读取草稿，维护者可发布但不可管理授权或停用模块。
- 账号停用、模块授权撤销和令牌撤销对后续请求生效。
- 重置密码使已有 Cookie 与访问令牌失效。
- 只读令牌不能写入或管理账号。
- 草稿代码及文档与当前发布隔离。
- 新发布替换当前内容，旧序号不再下载，失去引用的旧内容被清理。
- 过期草稿修订、无效发布和损坏内容不破坏当前发布。
- 数据库触发器注入发布中途失败，验证文件清单与元数据同时回滚。
- ZIP 路径穿越、绝对路径、保留名称、大小写重复、文件目录冲突、超限解压及链接条目被拒绝。
- 普通多文件上传、ZIP 替换、目录和 `.meta` 保留、草稿文件移除。
- 上传授权预检不保留过期草稿对象，拒绝覆盖其他编辑者的新修订。
- 分类树循环、删除被发布引用的分类和停用最后一个管理员被拒绝。

`node --check src/ModuleRepository.Web/wwwroot/app.js`：通过。

## 本机浏览器实际操作

使用独立 `.local/preview-data`，与启动脚本默认 `.local/data` 分离。测试账号使用临时随机凭据，不写入源码、文档和 Git。

已实际完成：

1. 初始化管理员并进入首页。
2. 创建分类、模块，填写功能、环境、标签和 Markdown 示例。
3. 输入代码并保存为草稿文件。
4. 发布首个版本，查看已发布说明及文件清单。
5. 通过浏览器文件选择器上传文档，确认只增加草稿文件。
6. 创建普通账号，为示例模块授予使用权限。
7. 以普通账号登录，确认可见授权模块，详情没有编辑、发布和授权操作，也看不到新增草稿文件。
8. 以普通账号从页面下载当前发布 ZIP，浏览器收到下载文件。
9. 停止并重新启动服务，原管理员会话、分类和已发布模块继续可用。

管理页已进行桌面尺寸截图检查。尚未进行真实手机浏览器验收或远程多人并发负载验证。

## 验证边界

这份记录只证明阶段 A 的本机实现与上述验证结果。尚未验证远程部署、反向代理、HTTPS、开机启动、项目目录更新、MCP/Skill 接入或完整 V1 流程。

当前是初始数据库 schema，尚无从未来旧 schema 自动升级的迁移程序。全文检索采用授权范围内字段及文档文本匹配，尚未引入 FTS 索引或语义检索。
